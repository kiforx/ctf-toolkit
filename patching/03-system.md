# Patching: Система / Local Privesc

**Навіщо:** піднявся до root через misconfig (SUID, sudo, cron, слабкий пароль, writable-файл) → закрий саме цей вектор, щоб суперник не піднявся так само. + утримання вершини (`king.txt`, зміна root-пароля).
**Коли:** після root; закриваєш шлях, яким піднявся.
← [README](README.md) · [00-method](00-method.md) · механізми: [perms/SUID/cap](../04-techniques/linux-perms-suid-cap.md) · [cron/services](../04-techniques/cron-services.md)

> Патчимо **свій** вектор. Не ламаємо сервіси й систему, не чіпаємо прапорці. Бекап перед зміною прав.

## 0. Утримання вершини (king.txt)
```bash
id                                   # переконайся uid=0(root)
echo '<НАЗВА_КОМАНДИ>' > /king.txt    # вписати свою команду (уточни точний шлях у платформи)
cat /king.txt                        # перевір
# змінити root-пароль, щоб суперник зі знайденим паролем не ввійшов:
passwd root
# змінити паролі адмін-юзерів, чиї креди витекли:
passwd <admin_user>
```
> `king.txt` платформа читає періодично. Якщо суперник перепише його — ти втратив вершину; тому **закрий вектор, яким заходили** (нижче), а не лише перепиши файл.

## 1. Слабкі / витеклі паролі
**Як підняв:** пароль із `config.php`/`.env`/history підійшов як системний (reuse), або слабкий пароль юзера.
```bash
passwd <user>                        # змінити пароль юзера, чий креденшл витік
# прибрати креди з місця витоку (щоб не читали далі):
#   напр. винести пароль із config.php у змінну оточення, або хоч змінити його всюди
grep -rEi 'passw|secret|DB_' /var/www /opt 2>/dev/null   # де ще лежить той пароль
```
**Перевірка:** старий пароль через `su <user>` → не пускає; сервіс, що юзав цей пароль (БД/додаток), оновлено й працює.
**Пастка:** змінив пароль БД-юзера — онови його **в конфігу додатка** ([02-services](02-services.md#бази-даних)), інакше зламаєш сайт.

## 2. SUID-бінар
**Як підняв:** нетиповий SUID-бінар (`find / -perm -4000`) дав shell/читання від root.
```bash
ls -la /path/vuln-suid                        # подивитись, що це
cp -a /path/vuln-suid /root/backups/          # бекап самого бінаря (на всяк)
chmod u-s /path/vuln-suid                      # ПРИБРАТИ SUID-біт (головний патч)
# перевірка — SUID зник:
find / -perm -4000 -type f 2>/dev/null | grep vuln-suid   # має зникнути
```
**Перевірка:** `./vuln-suid` більше не дає root (euid не 0); **якщо бінар — частина легітимного сервісу**, переконайся, що сервіс ще працює без SUID (часто працює).
**Пастка:** **не чіпай стандартні** SUID (`/usr/bin/passwd`, `sudo`, `mount`, `ping`, `su`) — прибрати в них SUID зламає систему. Патч лише **нетиповий** бінар, через який заходив.

## 3. Cron / writable-скрипт
**Як підняв:** cron від root запускав скрипт, у який ти міг писати (дописав reverse shell / SUID-копію).
```bash
ls -la /path/cronned.sh                        # чий власник, хто може писати
cp -a /path/cronned.sh /root/backups/
# 1) прибрати ЧУЖІ дописані рядки (свій payload і суперників):
nano /path/cronned.sh                          # видалити рядки типу 'bash -i >& /dev/tcp/...' , 'chmod +s'
# 2) виправити права, щоб ніхто сторонній не писав:
chown root:root /path/cronned.sh
chmod 755 /path/cronned.sh                      # або 700 — лише root пише/виконує
# 3) якщо cron тягне бінар/команду без повного шляху (PATH hijack) — виправити скрипт на абсолютні шляхи
```
**Перевірка:** `ls -la /path/cronned.sh` → власник root, не world-writable (`-rwxr-xr-x`); cron і далі виконує скрипт (сервіс живий); дописати туди вже не можна з-під звичайного юзера.
**Пастка:** не видали сам cron-скрипт/задачу, якщо це легітимна робота сервісу — лише **забери право запису** й **прибери чужі рядки**. Почекай цикл cron, щоб переконатись, що не зламав.

## 4. Sudo misconfig
**Як підняв:** `sudo -l` дозволяв команду, через яку escape до root (GTFOBins).
```bash
cp -a /etc/sudoers /root/backups/sudoers.bak
visudo                                          # РЕДАГУВАТИ ЛИШЕ через visudo (перевіряє синтаксис!)
# прибрати/звузити небезпечний рядок, напр.:
#   ДО:  webuser ALL=(ALL) NOPASSWD: /usr/bin/awk      # awk → root
#   ПІСЛЯ: видалити цей рядок, або замінити на конкретну безпечну команду без escape
```
**Перевірка:** `sudo -l` від того юзера → небезпечної команди вже нема; легітимні sudo-права (якщо є) лишились.
**Пастка:** **тільки `visudo`** — прямий `nano /etc/sudoers` з помилкою зламає sudo для всіх. visudo перевіряє синтаксис перед збереженням.

## 5. Writable-файли / world-writable
**Як підняв:** world-writable системний файл/скрипт, який запускає root; або writable у чужій теці.
```bash
# знайти небезпечні (довідково — не міняй усе підряд!):
find / -perm -o+w -type f 2>/dev/null | grep -vE '^/proc|^/sys|^/dev'
# прибрати запис у КОНКРЕТНОГО вразливого файлу, яким заходив:
cp -a /path/writable -t /root/backups/
chmod o-w /path/writable                        # прибрати запис для «інших»
chown root:root /path/writable                  # за потреби
```
**Перевірка:** `ls -la /path/writable` → без `w` для others; файл/скрипт далі використовується сервісом.
**Пастка:** не знімай запис масово по всій ФС (`chmod -R`) — зламаєш легітимні каталоги (напр. `/tmp` має бути writable). Патч точково.

## 6. Чужий SSH-ключ / доступ
```bash
# прибрати лишні/чужі ключі з усіх authorized_keys:
for f in /root/.ssh/authorized_keys /home/*/.ssh/authorized_keys; do
  [ -f "$f" ] && echo "=== $f ===" && cat -n "$f"       # перегляд → видалити сторонні рядки вручну
done
nano /home/<user>/.ssh/authorized_keys          # лишити тільки легітимні
```
**Перевірка:** вхід чужим ключем → відмова; твій/легітимний доступ лишився.

## 7. Старе ядро (kernel exploit)
**Як підняв:** застаріле ядро → kernel-exploit до root.
> **На KotH оновлення ядра під час гри — ризиковано** (потребує reboot → сервіс падає → мінус бали; reboot часто **заборонений**). Реалістичний підхід:
- **Не** перезавантажуй машину заради оновлення ядра.
- Натомість закрий **інші** вектори (SUID/sudo/cron/креди), щоб суперник не дійшов до kernel-кроку, бо kernel-exploit зазвичай — **останній** крок після foothold.
- Прибери з доступних місць бінар/експлойт ядра, якщо суперник його туди залив (`find /tmp /dev/shm -newermt ...`).

## Загальна перевірка після system-патчу
```bash
id                                              # ти ще root, king.txt на місці
systemctl is-active <ключові сервіси>           # усе active
# повтори свій вектор privesc (SUID/sudo/cron) з-під звичайного юзера → має провалитись
```
