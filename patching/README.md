# Patching / Defense — технічна база (KotH)

На основному етапі (King of the Hill) мало зайти й взяти root — треба **закрити вразливість, якою ти зайшов**, щоб 2 інші команди у твоїй групі не пройшли тим самим шляхом. При цьому **сервіс має лишатися живим**. Патчинг тут — половина балів.

> **Якщо ти ніколи не патчив — почни звідси, потім [00-method](00-method.md).** Нижче — філософія, правила й золотий алгоритм. Конкретні команди «до/після» для кожного вектора — у тематичних файлах.

## Навіщо патчити (логіка KotH)
- Ти і ще 2 команди сидите на **одній машині**. Хто тримає root і свою назву в `king.txt` — тому капають бали.
- Якщо суперник пройде тим самим шляхом, що й ти, — він тебе скине. **Патч = ти зайшов, вони вже ні.**
- **Головний трюк (із брифу):** добрий патч лишає сервіс **живим і робочим**, просто вже невразливим. Суперники бачать «живий сервіс», лізуть у вразливість, якої **вже немає**, і марнують час. Поганий патч (вбитий сервіс) — навпаки: одразу видно, що «тут патчили», + знімає бали за мертвий сервіс.

## 🚫 ПРАВИЛА (порушення = бан, SG main)
| НЕ можна | Чому |
|---|---|
| **Блокувати інших фаєрволом** (`iptables -A INPUT -s <ip> -j DROP` і т.п.) | **Пряма заборона правил.** Патчимо саму діру, а не ріжемо доступ |
| Вимикати/видаляти сервіс, зупиняти машину | Сервіс має відповідати; моніторинг високий |
| Видаляти/міняти прапорці, системні файли | Бан |
| «Вбити» сервіс патчем (не відповідає на легітимний запит) | Гірше за відсутність патчу: мінус бали + питання організаторів |
| Атакувати чужі IP (навіть із захопленої машини) | Бан |

> **Запам'ятай головне:** патч = **виправити вразливий код/конфіг** так, щоб легітимний функціонал працював, а експлойт — ні. **Не** фаєрвол, **не** видалення сервісу, **не** «зламати, щоб ніхто не зайшов».

## 🥇 Золотий алгоритм (для КОЖНОГО патчу)
```
1. ЗАФІКСУЙ як ти зайшов   → запиши вектор у нотатник (для відкату й пояснення організаторам)
2. ЗНАЙДИ вразливе місце   → який файл коду / який конфіг / який сервіс
3. BACKUP перед зміною     → cp -a файл файл.bak   (щоб відкотити, якщо зламав)
4. ПАТЧ мінімально         → виправ саме діру, не чіпай робочий функціонал
5. ПЕРЕВІР СЕРВІС ЖИВИЙ     → легітимний запит → працює? (напр. сайт відкривається, логін іде)
6. ПЕРЕВІР ДІРУ ЗАКРИТО     → той самий експлойт → вже НЕ працює
7. ЗАПИШИ «вектор → як пропатчив» → для організаторів і для себе
```
Детально кожен крок (як знайти веб-корінь, як безпечно перезапустити сервіс, як робити бекап) — [00-method](00-method.md).
