# Cheatsheet: Reverse Engineering (швидка тріаж)

Коли трапився невідомий бінар: кастомний сервіс на нетиповому порту, SUID-файл, програма у веб-корені чи завантажена з FTP/LFI.
Мета — не повний RE, а швидко знайти прапорець усередині, захардкоджений пароль/логіку або як обійти перевірку.
← [ports](../08-ports/README.md) · [perms/SUID](../04-techniques/linux-perms-suid-cap.md) · [grep/find](grep-find.md)

## 1. Тріаж (спершу завжди це)
```bash
file ./bin                      # тип: ELF 64/32, статичний, stripped?
strings -n8 ./bin | less        # читабельні рядки — часто прапорець/пароль/URL одразу тут
strings -n8 ./bin | grep -iE 'pass|key|flag|secret|http|/bin/'
strings -el ./bin               # 16-бітні (UTF-16) рядки — інколи ховають тут
./bin                           # просто запустити й подивитись поведінку/підказки
nm ./bin 2>/dev/null | grep ' T '   # власні функції (якщо не stripped)
checksec --file=./bin           # захисти (NX/PIE/canary) — орієнтир складності
```
Пошук прапорця прямо у бінарі:
```bash
strings -n6 ./bin | grep -aoE 'b[-_.]*e[-_.]*s[-_.]*t[-_.]*C[-_.]*T[-_.]*F[-_.]*\{[[:alnum:]_]+\}:[A-Za-z0-9]+'
```

## 2. Динаміка (швидше за статику для «що воно робить»)
```bash
ltrace ./bin                    # виклики бібліотек: видно strcmp(ввід,"пароль"), memcmp
strace ./bin                    # системні виклики: open/read файлів, мережа
ltrace -s 200 ./bin             # довші рядки в аргументах
# ввід порівнюється з секретом → ltrace покаже обидва аргументи strcmp
```
Мережевий бінар (слухає порт): запустити локально, підключитись `nc`, подивитись протокол у `strace`.

## 3. Статичний аналіз
```bash
objdump -d ./bin | less              # дизасембл (швидко, без GUI)
objdump -d ./bin | grep -A3 '<main>' # логіка main
r2 -A ./bin                          # radare2: aaa; afl (функції); pdf @main; iz (рядки)
```
Ghidra (GUI, якщо є час і бінар складний): декомпіляція у псевдо-C — найзрозуміліше для medium-задач. Для CTF-тріажу зазвичай вистачає `strings`+`ltrace`.

## 4. Часті швидкі перемоги
- **Hardcoded compare:** `ltrace` показує `strcmp(ввід, "s3cr3t")` → пароль у другому аргументі.
- **Прапорець по символах:** порівняння по одному байту → зібрати зі `strcmp`/`cmp` у `ltrace`/дизасемблі.
- **Кодування:** рядок виглядає як base64/hex → `base64 -d` / `xxd -r -p`; XOR-ключ часто поруч у `strings`.
- **Патч перевірки (локальний бінар):** інвертувати умовний перехід, щоб пройти перевірку:
  ```bash
  objdump -d ./bin | grep -i 'jne\|je\|jz'     # знайти перехід після порівняння
  # у r2: s <addr>; "wa jmp <ok>"; або замінити je↔jne (один байт 74↔75)
  ```
- **Env/аргумент:** програма читає `getenv("...")` чи `argv` — видно у `strings`/`ltrace`.

## Пастки / куди далі
- `stripped` + статичний → важче; спершу вичавити максимум зі `strings`+`ltrace`, а не лізти в дизасембл.
- Запуск невідомого бінаря — на СВОЇЙ цілі/у своєму середовищі; не запускати деструктивного наосліп.
- SUID-бінар з вразливою логікою → шлях до root: [perms/SUID/cap](../04-techniques/linux-perms-suid-cap.md).
- Знайдені креди/URL → [credentials-reuse](../04-techniques/credentials-reuse.md) · сервіс на порту → [ports](../08-ports/README.md).
